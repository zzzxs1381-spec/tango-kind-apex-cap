## 2. Продукт

Пользователь один раз связывает устройство с кабинетом и разрешает системный VPN, далее нажимает «Подключить». Приложение диагностирует сеть, допускает только реально доступные адаптеры, выбирает основной маршрут и до двух проверенных резервов, поднимает туннель, проверяет DNS и интернет через VPN, отслеживает обрывы. Не придумывай резерв, если его нет. AIMA советует; детерминированные ограничения и свежие измерения принимают решение. Postgres хранит истину, Qdrant хранит сходство; неисправность Qdrant не ломает соединение.

Требуемые состояния: IDLE, PREPARING, DIAGNOSING, SELECTING_ROUTE, CONNECTING, HANDSHAKING, TUNNEL_UP, VERIFYING, CONNECTED, DEGRADED, FAILING_OVER, RECONNECTING, OFFLINE, ERROR. Смена поколения соединения аннулирует старые проверки. CONNECTED допустим только при живом движке, TUN_INTERFACE_UP, DNS_OK и INTERNET_OK текущего поколения. Проверки должны быть явно привязаны к Android VPN Network; открытый напрямую сокет не доказывает VPN. Сохранённый boolean и успешный запуск ядра также не являются доказательством.

## 3. xf-tls1

TLS 1.3 only, ALPN xf-tls1; SNI передаётся и проверяется живым handshake с нашим edge. Сертификат self-signed; pin — SHA-256 DER leaf certificate в формате sha256/base64. Pin поступает по аутентифицированному доверенному API; не делай trust-on-first-use, insecure=1, trust-all без обязательной последующей проверки. Сверяй срок сертификата и pin до AUTH. Не заявляй, что чужое SNI делает трафик неотличимым от Microsoft/Apple/Cloudflare: собственный ALPN и поведение доступны наблюдателю. Не обещай обход ТСПУ.

Уточни wire-формат до кода и согласуй клиент/сервер:
AUTH <короткоживущий подписанный токен> LF; ответ OK LF. Максимум строки 4096 байт.
Каждый frame: u32be length (type+payload), u8 type, payload; длина 1..65536.
OPEN=1: u32be streamId>0, u16be hostByteLength, ASCII host, u16be port.
OPEN_OK=2: u32be id. OPEN_ERR=3: u32be id + UTF-8 generic reason.
DATA=4: u32be id + 1..16384 bytes. CLOSE=5: u32be id, EOF отправляющего направления (half-close).
PING=6/PONG=7: непрозрачный nonce до 32 bytes.
Отклоняй неизвестные типы, некорректные длины, повторные id, DATA до OPEN_OK, неразрешённые назначения; ограничивай сессии, потоки, очереди, idle и AUTH timeouts. Отмена закрывает все ресурсы. Никаких открытых прокси, чужих SSH-ферм, payload injector или перехвата содержимого приложений.

Edge в этом контуре слушает только 127.0.0.1. Внешняя доступность требует отдельного проверенного TCP ingress; localhost на сервере не доступен телефону напрямую. Не меняй bind на 0.0.0.0 ради демонстрации. Selftest получает отдельный токен, разрешающий ровно собственный локальный echo endpoint; обычные токены не могут достигать loopback/private/metadata адресов. Проверяй resolved IP до connect, закрепляй проверенный адрес, предотвращай DNS rebinding. Не журналируй AUTH, host, payload, DNS-запросы и пользовательские IP.

## 4. PacketBridge и Android

Используй существующее закреплённое нативное Xray TUN ядро для обработки TCP, сегментации, retransmit и backpressure. Не пиши игрушечный TCP стек. Для TLS13_SNI допустима цепь TUN → native TCP stack → аутентифицированный loopback SOCKS → xf-tls1 OPEN → edge → destination. SOCKS слушает только loopback со случайными credentials, UDP ASSOCIATE отвергает. Все внешние tunnel sockets защищаются VpnService.protect до connect; приложение не исключается из VPN целиком.

DNS из TUN должен реально работать: локальные DNS-запросы переводятся в TCP DNS внутри туннеля. Остальной UDP явно блокируется, capability udp=false/avoidUdp=true. Не рекламируй поддержку QUIC, звонков и игр. IPv6 не рекламируется без измерения и поддержки; исключи утечки семейства через системный Builder. Используй MTU 1280 как начальную настройку, а не как доказанное оптимальное значение.

VpnService.prepare, foreground notification, Builder.establish, обработка отказа/отзыва разрешения, stop/restart и освобождение fd. Always-On meta-data true только при реализованном восстановлении сохранённого профиля. Секреты храни через Android Keystore, запрети backup. Не сохраняй CONNECTED как переживающую рестарт истину. Удерживай TUN при временном обрыве для fail-closed. Системную защиту при смерти процесса обеспечивает настройка Android «Блокировать соединения без VPN» — маршрута по умолчанию недостаточно.

TunnelEngine: start, stop, restart, status, health, stats, migrate. Реализуй ограниченный reconnect с jitter/backoff и отменой, без параллельных движков. В ходе миграции CONNECTED сбрасывается; существующие TCP сессии могут оборваться. Только подтверждённые маршруты — кандидаты failover. Ошибки связи с telemetry не должны ломать здоровый туннель; события имеют session/generation/sequence, ограниченную очередь и идемпотентность. Не имитируй успешную запись при отказе Postgres.

## 5. Native API и стыковка

GET /api/native/config принимает probe bearer token. Возвращает sessionId, expiresAt, protocol, endpoint, SNI, pin, auth token и реальные capabilities. Token выдаёт сервер после существующей авторизации/проверки доступа; служебный issuer не является заменой аккаунтов и trial.
GET /api/native/edge запускает single-flight lazy edge/selftest и возвращает pin, TLS version, ALPN, observed SNI, handshakeMs, echo.ok, checkedAt, scope=local-selftest. Этот результат не доказывает доступность edge из РФ.
POST /api/native/stage проверяет bearer, session, generation и sequence, фильтрует поля и записывает Postgres. События native-reported не являются аппаратной аттестацией. Никогда не позволяй браузеру установить общий connected=true. Если UI отображает полученную с телефона телеметрию, явно подписывай устройство и возраст измерения.
GET /api/native/verify возвращает непредсказуемый nonce без cache/redirect для проверки через VPN. Верификатор сверяет ожидаемый ответ по валидному HTTPS. Не отключай публичную CA-проверку API.
Сайт стартует своим прежним startup, edge — отдельным ленивым сервисом: отказ selftest не должен выводить сайт из строя. Новые маршруты можно проксировать на loopback sidecar. Отсутствующие secrets/DB/endpoint дают явный unavailable, а не fallback на fake memory.

## 7. Проверки и сдача

Автономный selftest обязан подтвердить TLS1.3+SNI+ALPN+pin+AUTH+OPEN+двусторонний HTTP echo. Негативные тесты: TLS1.2, неверные pin/ALPN/SNI/token, malformed/oversized frames, duplicate ids, private target, expiry, half-close, ресурсные лимиты, повторный selftest и работоспособность после ошибки.
Проверь API auth, redaction, idempotency, stale events и запрет fake CONNECTED. Android: unit tests, compilation, lint, APK CI. Потом настоящий телефон: разрешение, DNS+HTTPS через VPN, UDP/IPv6 leak checks, loss/reconnect, сеть Wi-Fi↔LTE, kill switch, Always-On reboot, revoke и остановка. Без телефона пометь эти gates как NOT RUN. Без подписанного release и store receipt не заявляй публикацию.

Верни: ссылку на ветку/PR, полный промпт, код, команды/CI результаты, проверяемый selftest JSON, APK если сборка реально прошла, Figma, таблицу «доказано / не проверено / блокер». Если доступ отсутствует, заверши всё независимое и укажи точный недостающий доступ. Не выдавай исходники за полностью запущенный сервис.
