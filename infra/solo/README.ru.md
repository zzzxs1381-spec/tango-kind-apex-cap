# XFreedom: один зарубежный Ubuntu VPS

Комплект разворачивает личный VPN и закрытую панель XFreedom на одном сервере.
Старые три IP не используются. Нужен новый сервер с публичным IPv4, Ubuntu
22.04 / 24.04 / 26.04 LTS, архитектурой amd64 или arm64, минимум 2 ГБ RAM+swap
и 8 ГБ свободного диска. Для сборки предпочтительны 4 ГБ RAM.

## Что устанавливается

| Компонент | Доступ | Назначение |
| --- | --- | --- |
| Xray, VLESS + REALITY + Vision | TCP/443 | Основное подключение |
| Hysteria 2 + Salamander | UDP/443 | Дополнительный транспорт |
| XFreedom Control Center | Только 127.0.0.1:8080 | Панель через SSH |
| PostgreSQL 18.6 | Внутренняя сеть Docker | Постоянная база |
| Qdrant 1.19.0 | Внутренняя сеть Docker, API key | Хранилище векторов |
| systemd + проверки | На самом VPS | Перезапуски и диагностика |

Два транспорта находятся на одном IP. При отключении VPS или блокировке его
адреса могут перестать работать оба. Межсерверного резерва теперь нет.
AmneziaWG/WireGuard mesh для одного узла не устанавливается.

## Запуск

Используйте приложенный `xfreedom-one-server.sh`: в нём закреплён проверенный
коммит. Скопируйте его на **новый** сервер. В PowerShell, из папки загрузки:

```powershell
scp .\xfreedom-one-server.sh root@NEW_SERVER_IP:/root/
ssh root@NEW_SERVER_IP
```

В открывшемся терминале Ubuntu:

```bash
bash /root/xfreedom-one-server.sh NEW_SERVER_IP
```

Замените `NEW_SERVER_IP` новым адресом. Установщик также может спросить его сам,
если аргумент не указан. При нестандартном SSH-порте добавьте `-P PORT` к `scp`
и `-p PORT` к `ssh`. Приватный ключ задаётся через `-i PATH`.

Для прямого запуска из проверенного checkout:

```bash
sudo bash infra/solo/install.sh --preflight NEW_SERVER_IP
sudo bash infra/solo/install.sh NEW_SERVER_IP
```

При `--preflight` сам install.sh не меняет сервер; обёртка bootstrap.sh при
необходимости устанавливает Git/Python до получения исходников.

Установка прерывается при занятом порте, несовпадении SHA256, неподходящей ОС,
ошибке конфигурации, сборки, базы или проверки транспорта. Повтор той же
команды сохраняет UUID, пароли, ключи и сертификат. Смена IP или версии поверх
завершённой установки намеренно отклоняется: для неё нужна миграция.

Существующие SSH-настройки не изменяются. Если UFW уже включён, добавляются
разрешения TCP/443 и UDP/443. Выключенный UFW не включается автоматически.
Firewall в панели хостера также должен пропускать эти два порта; установщик
не получает доступ к панели хостера и не может изменить её правила.

## Подключение телефона и ПК

На сервере выполните:

```bash
sudo xfreedom-solo links
```

Импортируйте одну из ссылок `vless://` в клиент. `chrome` и `firefox` — два
отпечатка одного транспорта, а не два отдельных сервера.

Для Windows подходит [v2rayN](https://github.com/2dust/v2rayN/releases), для
Android — [v2rayNG](https://github.com/2dust/v2rayNG/releases). Загружайте клиент
из официального репозитория. На ПК включите TUN и маршрут всего трафика через
VPN; системный HTTP proxy охватывает не все приложения. На Android используйте
VPN-режим без исключения нужных приложений. Проверьте DNS и IPv6 на клиенте:
одна настройка сервера не гарантирует отсутствие обходных маршрутов устройства.

Архив всех профилей скачивается в отдельном PowerShell-окне:

```powershell
scp root@NEW_SERVER_IP:/etc/xfreedom-solo/client-bundle.tar.gz .
```

Внутри — REALITY-ссылки, JSON для Xray, JSON для нативного клиента Hysteria и
сертификат `server.crt`. Это приватные данные доступа.

Hysteria запускается из папки с сертификатом:

```bash
hysteria client -c hysteria-client.json
```

Получится SOCKS5 на `127.0.0.1:10809`; для полного охвата устройства требуется
совместимый TUN-клиент. JSON Hysteria не является профилем Xray: импортировать
его в произвольное приложение нельзя. Для Hysteria намеренно нет ссылки с
`insecure=1`: некоторые клиенты теряют параметр pinSHA256 при импорте. В этом
профиле доверие задаётся сертификатом, проверка TLS включена.

## Панель управления

Оставьте отдельное SSH-соединение открытым:

```powershell
ssh -N -L 8080:127.0.0.1:8080 root@NEW_SERVER_IP
```

Откройте `http://localhost:8080/admin` на своём ПК. Публичного веб-адреса панели
эта установка не создаёт. Базы не публикуются наружу. Клиент VPN не получает
доступ к loopback, приватным подсетям или панели через туннель.

Панель показывает проверки PostgreSQL, Qdrant, служб и watchdog. Данные старше
трёх минут не считаются свежими. Model Router, MCP, Temporal и AI-агенты ещё
не реализованы: наличие контейнера Qdrant само по себе не создаёт память ИИ.
Заказы и другие старые функции интерфейса не превращаются этим установщиком
в коммерческий VPN-биллинг. Комплект предназначен для личного подключения.

## Диагностика и восстановление

```bash
sudo xfreedom-solo status
sudo xfreedom-solo probe
sudo xfreedom-solo logs
sudo xfreedom-solo repair
sudo xfreedom-solo backup
```

`probe` поднимает временные авторизованные клиенты и передаёт HTTPS и UDP DNS
через оба транспорта. Проверка проводится **с VPS**. В её отчёте отдельно
указано, что внешняя доступность и сеть пользователя в России ещё не проверены.

Watchdog раз в минуту проверяет собственные службы и контейнеры. Неактивные
службы перезапускаются, unhealthy-контейнеры восстанавливаются; попытки
ограничены интервалом десять минут. systemd отдельно ограничивает частые
аварийные перезапуски. Блокировка IP, недоступный сайт и проблемы оператора
не запускают бесконечное изменение конфигурации. Код и протоколы не обновляются
автоматически. Сертификат также не ротируется скрыто от клиентов.

Журнал установки находится в `/var/lib/xfreedom-solo/install-*.log`. При ошибке
сначала исправьте указанную причину, затем повторите ту же команду. Не удаляйте
`state.json`, volumes или каталоги баз ради повторного запуска.

## Резервные копии

Каждый день в 03:15 по часовому поясу VPS создаются PostgreSQL dump, полный
snapshot Qdrant и архив конфигурации. Хранятся семь завершённых копий в
`/var/lib/xfreedom-solo/backups/`. Архивы содержат секреты и доступны root.

Эти копии находятся на том же VPS: потеря диска может уничтожить и оригинал,
и копии. Скачайте их отдельно либо подключите внешнее хранилище следующим
этапом. Автоматическая отправка в неизвестное облако не настроена.

В CI PostgreSQL dump восстанавливается в отдельную тестовую БД; повторное
создание контейнера также проверяется на сохранность записей. Для настоящего
аварийного восстановления сначала восстановите прежние версии и конфигурацию,
затем базу и Qdrant snapshot по штатной процедуре. Не запускайте восстановление
поверх работающей базы без отдельной копии текущего состояния.

## Версии и границы проверки, 9 сентября 2026

Xray закреплён на последнем релизе с признаком stable в GitHub — v26.3.27.
На дату проверки существует более новый v26.9.9, но он помечен prerelease.
Hysteria закреплена на app/v2.12.2. Для amd64/arm64 SHA256 бинарных файлов
записаны в `versions.json` по метаданным официальных релизов. Все изменения
сначала проходят CI. Установка проверяется на Ubuntu 24.04 amd64; остальные
указанные сочетания поддержаны кодом, но не подтверждены такой же машиной CI.

Проверки TCP/UDP и браузера не доказывают работу WhatsApp-звонков, Telegram,
YouTube и Instagram у каждого провайдера Крыма, Ингушетии, Дагестана или Москвы.
Для этого требуется подключённое устройство в соответствующей сети. OONI
подтверждает различающееся поведение блокировок Telegram между сетями; из этого
не следует существование универсального профиля для всей страны.
